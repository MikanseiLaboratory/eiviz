---
title: インスタントリプレイ
description: 全カメラを常時録画し、重要な場面をマークしてそのまま送出する
---

インスタントリプレイは複数のシーンを常時録画し、直近数分からクリップを切り出して、番組を止めずに再生できます。ProfessionalライセンスとProモジュールが必要です。

## プロジェクトへの追加

リプレイは、プロジェクトにリプレイ入力がある間だけ存在します。

1. **入力の追加**で **リプレイ** を選びます。このカテゴリはプランとモジュールがリプレイを許可している場合のみ表示されます。
2. リプレイ入力1つがリプレイチャンネル1本に対応し、`Replay A`、`Replay B`…（最大26本）という名前になります。

リプレイ入力が無い間はリプレイウィンドウとリプレイ設定は開けず、セッションにもリプレイの情報は保存されません。最後のリプレイ入力を削除すると確認が出て、設定・イベント・プレイリストごと削除されます。削除されたチャンネルをシーンのアニメーションがキューしていた場合は、そのキューだけが消え、セッションは壊れません。

## リプレイ設定

リプレイ設定はメインウィンドウから開く専用ウィンドウで、録画に必要な項目をまとめています。

- **保存先**: 1つ以上のドライブ。各アングルは必ずどれか1本のドライブに割り当てられ、1本のドライブに全アングルを入れるのが通常の構成です。1つのアングルが複数のドライブにまたがることはありません。残り時間は、空き容量から予約容量を引いた値をドライブ全体で合計して計算します。
- **画質**: HQ/SQ/LQ。自動で画質を落とすことはありません。
- **区画フレーム数**: 1つの区画ファイルに含めるフレーム数（既定: 120、範囲: 30〜1800）。
- **エンコードキュー**: アングルあたりの未エンコードフレーム上限です（既定: 6、範囲: 2〜60）。
- **書き込みバッファ**: 区画ファイルへ書く前のメモリ上限です（既定: 512MiB、範囲: 64〜8192）。
- **予約領域**: 各ドライブで空けておく容量（MiB）。
- **あふれたとき**: エンコードが追いつかないときにフレームを捨てるか、録画を止めるかを選びます。
- **ディスクが一杯になったとき**: 停止して通知する／古い区画から上書きする／使用中のクリップと保護イベント以外を上書きする、から選びます。
- **新しいクリップ**: 以降に追加するクリップに適用するトランジション。
- **アングル**: 各アングルは「シーンの合成結果」または「入力そのものの絵」を録画します。音声はMixing Unitのプログラムミックスか無音を選べます。入力を指定するアングルはシーンを組む必要がないため、カメラ1台を録るだけの構成が軽くなります。**OMT入力**のアングルでは録画方式に「パススルー」も選べます。パススルーは送られてきた圧縮フレームをそのまま保存するため、GPUからの読み戻しも再エンコードも行いません（そのぶん画質もCPUも消費しません）。録画フォーマット（解像度・フレームレート）は最初のMixing Unitから決まり、全アングルで共通です。
- **イベント作成時に自動でプレイリストへ追加する**: リプレイウィンドウで選択中のアングルを使います。推測したカメラには割り当てません。

アングル構成は録画中は変更できません。アングルを追加・削除するときは録画を停止してください。

## リプレイウィンドウ

リプレイウィンドウがオペレーターの操作面です。

- **アングル**: すべてのアングルをライブ表示します。クリックすると、マークとプレイリストで使うアングルになります。4本を超える場合は1つのコンパクトな表示にまとまります。
- **録画 / 停止**: 録画の開始と停止。状態行には残り時間（空き容量が無い場合はその旨）を、ヘルス行には書込/読出フレーム数、読出ロス、エンコード・書込の取りこぼし、区画数、キューの深さ、書込レイテンシを表示します。問題は「空き容量低下」「エンコード遅延」のように言葉でも表示します。
- **マークイン (I) / マークアウト (O)**: クリップの範囲をマークします。IN/OUT/尺がタイムコードで表示され、波形上にマーク位置（IN/OUT）と録画位置が描かれます。「マーク解除」で範囲を消します。
- **イベントリスト**: マークしたイベントと尺の一覧。保護（上書き対象から除外）、名前変更、削除、プレイリストへの追加ができます。イベントを削除しても、そこから作られたクリップは残ります。
- **プレイリスト**: チャンネルが順に再生するクリップの一覧。キュー、削除、タグ付け、そしてトランジション（カット/ディゾルブ）、トランジションの種類（重ねる/挿入する）、尺、ゲイン（−60〜+12dB）、ピッチ保持、再生速度、音声の取得元（自アングル/別アングル/無音）を編集できます。
- **トランスポート**: 再生、一時停止、1フレーム送り、ジョグ、25%/50%/100%、ライブ（録画位置へ復帰）。コマ送りとジョグはマーク範囲内に収まります。
- **キーボード**: `I`/`O` でマーク、`Space` で再生/一時停止、`←`/`→` で1フレーム送り、`L` で録画位置（ライブ）へ戻ります。
- **書き出し**: 選択中のクリップ／プレイリスト全体／このアングル／全アングルをMP4に書き出します。書き出しは録画のあるマシンで実行されます。

## トランジション

クリップのトランジションは、クリップ自身が指定していなければプレイリストの**新しいクリップ**設定を使います。

- **重ねる (Overwrap)**: 前後のクリップで尺を分け合います。前のクリップの終端と次のクリップの先頭が重なります。
- **挿入する (Additive)**: 尺をクリップの間に足します。プレイリスト全体は `A + 尺 + B` になります。挿入中は前のクリップの最終フレームと次のクリップの先頭フレームを保持し、その間でディゾルブします。

尺が0のディゾルブとカットは、時間を消費しません。

## 自動化パネルからの操作

vMix互換APIから録画・マーク・キュー・再生ができるため、Stream DeckやCompanionでリプレイを操作できます。各Functionは[関数リファレンス](/ja/developers/function-reference/)を参照してください。

シーンのアニメーションからもリプレイをキューできます。シーケンスのステップにチャンネルとクリップ（またはチャンネルの最新クリップ）を指定して再生させることで、進行表どおりに自動で再生できます。

ネイティブAPI（`eivizctl`）からも同じ操作ができます。`input add --kind Replay` でチャンネルとリプレイ設定が一緒に作られ、`replay configure --from-json` で保存先とアングルを書き込み、`replay angle --id N` でマークに使うアングルを選び、`replay record` / `mark-in` / `mark-out` / `cue` / `play` で操作します。`replay state` はセッションの設定とミキサーの実測値（録画状態、チャンネルの位置と速度、ドロップ数）をまとめて返すため、監視や自動化はこの1回の呼び出しで足ります。

## リモート

リモートからもリプレイを操作できます。録画・マーク・キュー・再生は録画側のマシンへ送られ、そこで作られたイベントとクリップはセッションとして返ってきます。

録画そのものは録画側のマシンにあります。録画状態、ヘルス、波形、アングルのプレビュー、MP4の書き出しは録画側のマシンにしか無いため、リプレイウィンドウはそれを表示し、録画していないマシンの数値を出すことはありません。フレームを確認しながらマークを切りたい場合は、録画側のマシンで操作してください。
